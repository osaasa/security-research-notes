# 証拠と編集方針

公開日: 2026-10-31

## 確認範囲

本人の過去の作業記録、保存された検証資料、管理リポジトリの静的確認をもとに編集した。今回Azure、RF機器、過去のDocker環境を再実行したものではない。

| 記事 | 主な根拠 | 収録しないもの |
|---|---|---|
| ARTEX | コード・コミット、Docker / MCPの作業記録 | 既存ソース一式、実API接続証明、生レポート全量 |
| Sentinel再クエリ | 合成データ検証資料、後続記録 | 内部ルール名、サポート原文、実行履歴原本 |
| WAF | 構築・応答・クォータ変更記録 | 実IP・ホスト名、クラウド識別子、元画面 |
| LogSeeder / Network / MDE | 導入・切り分け記録 | 認証設定、テナント・端末識別情報 |
| SDR | 機材・経験の本人申告、調査 | 第三者PDF、未確認の成功結果、IQ・位置データ |
| ローカルLLM | 導入・ツール連携記録 | 未測定性能、未購入機の実測 |
| GoldenEye | 改修レビュー資料 | 未照合の性能・テスト結果 |

## AIの寄与と人の判断

ChatGPT / Codexは構成理解、コード・設定検討、トラブルシューティング、文書化を支援した。目的・対象と採否の判断は人が行う。個々の過去ファイルで生成範囲を追跡できない場合、AI生成行数や自動実装率を示さない。

既存プロジェクトの機能を自分の新規開発として扱わず、Mockや合成例を実機の診断・侵害成功として扱わない。

## 残す項目

1. 実施日、バージョン、環境。
2. 目的と成功・失敗の基準。
3. 実行・確認コマンド。
4. 実測 / 合成 / Mockの区分。
5. ログの所在・ハッシュ、結果、未解決事項。

今回作成した例は`Synthetic example`と明示し、過去の実測証拠には使わない。顧客情報、個人の連絡先、実接続先、秘密値は掲載しない。第三者の資料を丸ごと転載せず、独自の解説にする。
